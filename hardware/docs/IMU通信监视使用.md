# 铰接小车双 IMU 通信监视

这是独立铰接小车项目的电脑端只读桌面窗口。它不调用车辆控制、不复位 MCU、不烧录、不向 USB RX 或 IMU 发送数据。

## 启动

在应用菜单搜索“铰接小车 IMU通信监视”，或在电脑终端运行：

```bash
bash '/home/gyt/钻探小车/清扫小车实机/启动IMU监视.sh'
```

启动脚本带单实例锁，重复启动不会抢占同一个 USB RX。运行依赖已有 Python 3.10 虚拟环境、pyserial 3.5 与系统 Tk 8.6，无新增网络服务。

默认 RX 端口从 `configs/usb_radio_host.json` 读取，保持之前确认的电脑 USB 插口映射。可明确指定其他接收端口：

```bash
./启动IMU监视.sh --port /dev/serial/by-path/实际RX路径
```

ST-Link 使用已识别的序列号 `33FF72064243323456261357`，通过只读 API 抽样读取固定诊断区，不暂停、复位或写目标芯片。若要使用其他工具烧录，先点“暂停 STM32 诊断”释放调试器。USB 与 ST-Link 的暂停按钮只影响监视器读取，不停止板上固件。

## 窗口中的四段链路

1. **STM32 读取 IMU**：前后有效帧累计数、实际源端计数频率、UART 错误和接收队列丢失。频率按 MCU 时间和计数差计算，不能用电脑诊断轮询频率冒充。
2. **24L01P 无线发送**：MCU 本次启动编号、整包完成数、片段成功/失败数、SPI 错误，以及等待/发送窗口内/窗口结束等状态。
3. **电脑 USB RX 接收**：监视器本会话实际收到的完整包、字节、CRC 错误、重复和乱序。不会把源端计数填进接收计数。
4. **完整包交付核对**：仅当电脑接收已覆盖某次启动的发送过程，且固件结束后留出接收时间，才对照同一个 boot_id 的整包完成数与实收数。若在发送早已结束后才打开监视器，会明确显示“未覆盖完整窗口”，不能拿 MCU 先前累计 100 包和新会话 0 包计算丢包。

## 下方三种数据来源

- **无线接收**：只画 USB RX 收到并通过 CRC 的真实数据。前后分别展示姿态角、三轴加速度、三轴角速度、接收频率、序号和原始遥测包。
- **STM32 旁路诊断**：用 ST-Link 查看最新有效 IMU 原始帧，可在无线窗口结束后继续观察。它是低频抽样查看，不是完整的 25 Hz 原始序列，也不能代替无线实收结果。
- **历史实测回放**：载入此前已验证的 100 包记录，可按 1×/2×/5× 播放。窗口明确标为历史数据；上方链路卡片仍表示实时状态，不把回放注入实时接收计数。离线模式则完全不打开设备。

前后是 A10/A3 接线身份；IMU 尚未装车。Yaw 是传感器输出，不等同于标定后的世界方向。界面不展示车辆位置、里程或未经标定的铰接角。缺失和过期数据不会补零；过期数值保留但灰显并显示年龄。

## 看一次完整实时无线过程

当前 MCU 是限时验证固件：每次启动约 5 秒后开始发射，约一分钟后自动结束。看到“发送窗口已结束”时，STM32 仍可继续采集，USB RX 没有新包属于预期行为。

测试目的：观察真实传感器数据到达 STM32、射频发送及电脑接收全过程，并核对同一启动编号的完整包计数。执行机器为当前开发电脑，先保持监视窗口开启、两只 IMU 及无线模块的已确认接线不变、电脑 USB RX 保持插着。

由用户完整拔除板卡 USB 供电与 ST-Link USB，等待 10 秒确认板卡及 IMU 指示灯熄灭，再按原样恢复供电；不修改任何信号线或跳帽。该动作会重新触发已有约 60 秒射频发送窗口，不重新烧录，不控制车辆。预期数据从等待状态转为两路实时曲线，源端仍各约 25 Hz、无线每路约 0.83 Hz；经过完整窗口后应看到同启动的 100/100 整包核对，具体以本次实测计数为准。

预计约 1–2 分钟。关闭窗口只结束电脑读取，板上发射按固件时间自行结束；立即停止板卡运行需断开全部相关供电。通过条件为两路完整无线包及 CRC 正常、同一 boot_id 的源端整包数与实收相符、无 SPI/UART/队列错误；界面打开、曲线来自旁路或历史回放，不等于实时无线通过。

## 自动记录

每次实时启动建立独立目录 `captures/monitor/<UTC时间>/`：

- `radio.bin`：USB RX 原始字节，及时刷新到磁盘。
- `radio.csv`：无线实收测量，含前后身份、启动编号、序号、两个独立时钟，以及有明确单位的九个值。
- `events.jsonl`：实际无线样本、原始 wire_hex、MCU 诊断快照和连接事件。
- `status.json`：当前连接、计数、频率和整包核对状态，原子更新。

“打开记录文件夹”可直接进入本会话目录。日志中的 MCU 时间是 UART 帧尾接收计时，主机时间是接收时刻，二者未宣称精确同步。序号缺口包含主动降频未上报的源帧，不能直接作为射频丢包率。

## 离线与验证

```bash
./启动IMU监视.sh --offline
/usr/bin/python3 -m unittest discover -s tests -v
```

离线默认载入此前真实验证文件 `captures/f103_radio_20261105/power_cycle_recovery/rx.jsonl`；原始记录被删除时会明确提示，不生成模拟测量替代。可使用 `--replay 实际文件路径` 指定其他兼容记录。

当前 70 项离线测试通过，包括监视器新增的分帧、CRC、缺失数据、重启清除旧通道、实时与旁路隔离、完整窗口核对和回放独立性。离线窗口已完成本机渲染检查，截图 `validation/imu_monitor_replay.png`。实时窗口已确认能读取两个通道各 25 Hz 的源端状态及 USB RX 连接；本轮可视化新启动的完整无线过程需在用户上电触发后另行记录。
