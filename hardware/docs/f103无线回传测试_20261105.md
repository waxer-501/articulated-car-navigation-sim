## 准备状态

此前运行的接收诊断固件已经证明双 IMU UART 接收正常；无线版本构建后，57 项已有/驱动测试及新增 4 项报告验收测试均通过（共 61 项）。无线版本已按授权写入，复位后的运行和无线状态仍未验证，不能声称链路已通过。

目标链路：真实两只 IMU406 → STM32F103C6T6A → SPI 裸 24L01P → 空中 → 电脑 USB RX 底板 → 只读接收器。树莓派当前未连接 RX，不计入本轮验收。

## 固件与写入范围

- 镜像：`build/f103_radio/f103_radio.bin`，6896 字节，SHA-256 `68b93dba6b86ed65107a737ccfd6a3e21a4850fd781eab963f0f6110806b0ff5`。
- ST-Link：`33FF72064243323456261357`；目标须为设备 ID 0x0412 / 32 KiB Flash。
- 烧录会替换 Flash 前 **7 个 1 KiB 页**并复位 MCU。
- 程序末尾保留 **2 KiB（0x08007800–0x08007FFF）**作为双页启动编号日志，每次启动提交一条 8 字节 counter/反码记录；日志满时轮换擦除旧页。先提交新启动编号，再允许 RF，避免断电后重用已发出的启动编号。代码最多使用前 30 KiB。
- 整个 Flash 会先稳定只读备份，写入后逐字节核对镜像、保留中间区域；末尾日志由新程序自行更新，单独记录。不会全片擦除或修改选项字节、读保护。
- 断电中断日志写入、日志页轮换及失败场景有独立假 Flash 测试。没有在本次测试中主动切电或重复复位实物。

GPIO 与已确认接线保持一致：前/后 IMU TX1 接 A10/A3；无线 SCK/MISO/MOSI/CSN/CE 接 A5/A6/A7/A4/B0。IMU 接收命令线可以连接 A9/A2，固件仍不启用串口发送，也不修改 IMU 输出频率。

## 射频配置及边界

先使用厂家 STM8 示例中的候选空中配置：信道 60（2460 MHz）、250 kbps、0 dBm、5 字节地址 `34 43 10 10 01`（SPI 发送顺序）、1 字节硬件 CRC、动态载荷、pipe-0 硬件自动 ACK。配置写入后核对寄存器及 TX/RX0 地址，不通过则不发射。IRQ 线不接，非阻塞轮询状态。

候选配置来自用户提供的泽耀资料包，尚未读取 USB RX 底板内的无线寄存器；是否匹配必须以真实 USB 收到完整 CRC 有效的 IMU 数据为证。硬件 ACK 不提供反向应用命令通道；两块 USB 底板仍按用户确认的 TX/RX 固定应用角色处理。

SPI 初始标称 500 kHz。发送 CE 脉冲单独计时，避免将 SPI 装载时间误算为 CE 高电平时间。MAX_RT、SPI 失败或 1 秒发送完成超时后释放当前旧包并计数，不阻塞双 UART 采集，也不自动重刷。

每个 32 字节遥测包分两次 16 字节发送，任意连续分段之间至少隔 300 ms，沿用此前 USB TX→RX 通过的低速条件。公平轮询前后两路，选择最新有效采集帧。每路上报约 0.8 Hz 是首轮调试目标，不把它说成两路均以 25 Hz 无线输出；UART 继续按 IMU 原有约 25 Hz 接收。

序号仍按每个有效 IMU 采集帧递增，所以 `sequence_gap` 包含主动只发最新帧而省略的采集帧。不能把其累计值直接叫作无线丢包率。无线交付另按 MCU 完成的整包计数与 USB 实收整包数对照。

## 执行说明

执行机器：当前开发电脑；目录 `/home/gyt/钻探小车/清扫小车实机`。保持 MCU、两只 IMU、裸 TX 无线模块和 ST-Link 已接线供电，RX USB 底板插在此前确认的电脑 USB 口 `1-1.2`，所有设备静止。不接车辆行驶、转向、机械臂或主轴接口。

本轮会明确烧录新无线固件，需要用户授权。默认入口仅预览，不打开硬件：

```bash
/usr/bin/python3 tools/verify_f103_radio.py
```

授权后测试入口为：

```bash
/usr/bin/python3 tools/verify_f103_radio.py --apply --output captures/f103_radio_20261105/first_run
```

入口先打开电脑 USB RX 9600/8N1 只读采集，随后备份、烧录、复位和核验。新固件每次启动后约 5 秒开始发送，约 65 秒结束发送（允许正在发送的整包完成），随后 CE 低并使无线芯片进入掉电状态，IMU 接收继续运行。USB 采集持续约 120 秒，包含起止静默段；整体预期约 2–3 分钟，实际耗时另行记录。

预期行为：两只 IMU 仅输出数据；F103 收集、封包并低速发射；USB RX 只接收并转交串口；电脑不向 RX 写任何数据。没有运动、使能或旋转。

停止：采集工具 Ctrl+C 会关闭电脑采集，不停止板上程序。固件本轮发射窗口会自行结束；立即停止板上发射需断开 MCU 和无线模块供电。烧录过程中不要拔线或中断；任何失败保留日志，不自动重新烧录或重启实物测试。

## 验收与输出

- 两路各至少收到 10 个完整真实 IMU 遥测包，主机重新计算 CRC 通过，启动编号与 MCU 一致。
- MCU 整包完成数与 USB 实收数相符，分段失败、编码错误和 SPI 错误均为零。
- 没有 UART 硬件错误或接收队列溢出，最终无线状态为已结束、固件故障标志为零。
- 不用“程序运行完了”“SPI 回读成功”或“硬件 TX_DS”单独作为无线回传通过的依据。

输出目录保存原始 USB 字节 `serial.bin`、含原始 32 字节 wire_hex 的 `rx.jsonl`、接收日志、烧录驱动日志、首尾 MCU 诊断快照和 `summary.json`。完整 Flash 备份/读回及烧录日志仍在 `captures/f103_flash/<UTC时间>/`。输出目录不能已存在，失败重测需保留旧记录并另建目录。

板载 3.3V 供电的电压和电流仍未测量。上一轮只证明关闭 RF 时 UART 采集正常；本轮另观察发送期间的采集、启动编号变化和错误，不据此声称已经完成电源裕量或最大通信距离验证。
