## 固件行为

源文件：`firmware/f103_capture/main.c`、`linker.ld` 和 `firmware/common/imu406_stream.*`。使用 ST 官方 F103x6 CMSIS 启动文件和设备头文件、ARM CMSIS 核心头文件；下载地址及散列锁定在 `configs/f103_cmsis_sources.json`，没有移植 MC02 的 H7 启动/外设代码。

- USART1/2 仅开启 RX，115200、8N1；A9/A2 保持输入，不发送任何 IMU 配置命令。
- PA4 拉高、PB0 拉低，保持无线模块 CSN 高、CE 低；不初始化 SPI，不发送无线数据。
- 不初始化 CAN、USB、PWM、电机或其他车辆接口。
- 使用内部 HSI 经 PLL 得到标称 64 MHz；失败时报告回退状态。时间戳是 MCU 接收到 UART 帧尾的标称微秒计数，并非 IMU 内部采样时刻。
- 中断只入队接收事件，主循环解析；各通道有独立有界队列，错误/溢出后丢弃不连续片段，不补零。
- 每 200 ms 将诊断信息发布到固定 SRAM 块（0x20000000、256 字节），ST-Link 读取前后版本校验，拒绝不一致快照。此调试视图最多更新 5 Hz；真实 UART 收帧计数保留完整累计量，不能将调试采样间隙当作无线丢包。
- 本固件仅是首次采集诊断版，不输出遥测 v1 无线包，不声称已经实现新板的无线驱动或每次启动的无线 boot_id。

当前构建占用 Flash 3776 字节，静态 SRAM 共 2688 字节（含诊断区，另预留至少 2 KiB 栈）。构建清单和镜像散列见 `build/f103_capture/build.json`。

## 测试说明及执行入口

目的：在静止状态确认前、后两只真实 IMU 的 UART 数据能分别到达 MCU，并通过协议校验、BCD 解码，独立于无线链路排查接线问题。

执行机器：当前开发电脑，在 `/home/gyt/钻探小车/清扫小车实机` 下执行。用户确认接线和供电后保持板卡、两只 IMU 静止，ST-Link 保持连接，不接车辆运动接口。用户已确认板载 3.3V 接线，电源未实测；本阶段关闭 RF 发射，不据此证明发射负载下供电稳定。

烧录属于另一个需明确授权的动作：它会覆盖 **Flash 前 4 个 1 KiB 页**中的原程序，并复位 MCU，使上述接收固件运行。工具先重新备份完整 Flash，指定 ST-Link 和 0x0412/32 KiB 目标，写入后完整读回比对镜像和其余 Flash；失败不自动重试，不修改保护或选项字节。未得到明确烧录授权前只可运行默认预览：

```bash
/usr/bin/python3 tools/flash_f103_capture.py
```

明确允许后，烧录入口为：

```bash
/usr/bin/python3 tools/flash_f103_capture.py --apply
```

随后采集约 30 秒，不移动传感器：

```bash
/usr/bin/python3 tools/f103_swd.py capture --seconds 30 --output captures/f103_20261105/imu_first_capture
```

该输出目录必须不存在；失败后保留原记录，诊断后另建新目录，不自动覆盖或重启测试。预期 IMU 按已有配置持续输出，MCU 仅接收；无线模块不发射，车辆没有行驶、转向、使能或其他动作。烧录和采集通常约 1–2 分钟，首次实际耗时仍待记录。

通过条件：30 秒窗口内两路均有多个独立有效帧、累计有效帧数持续增加，主机能独立复核原始校验/BCD，未发生新增 UART 错误或队列丢失、未检测到固件故障或重启。实际输出频率按收帧计数和 MCU 计时报告，不预设实物一定为 25 Hz。只看到串口字节、仅一只有效或程序运行完毕，均不能判定双 IMU 通过。

停止：采集时 Ctrl+C 只停止电脑读取；MCU 仍继续接收。断开板卡及外设电源才完全停止这一固件。烧录写入过程中不要拔线或中断；若工具报错，保留日志，先检查芯片状态，不自动重刷。

输出：烧录的前/后 Flash、日志和比对结果在 `captures/f103_flash/<UTC时间>/`；采集原始 SRAM 快照、原始 IMU 帧、测量值、计数和独立判定在采集目录的 `diagnostics.jsonl` 和 `summary.json`。本测试不验证无线或树莓派回传，也不修改另一条车辆控制链路。

## 仅构建、仅备份入口

```bash
/usr/bin/python3 tools/fetch_f103_cmsis.py
/usr/bin/python3 tools/build_f103_capture.py
/usr/bin/python3 tools/f103_swd.py build-reader
/usr/bin/python3 -m unittest discover -s tests -v
```

上述步骤不打开硬件。依赖本地 `.toolchain/` ARM GCC 10.3.1、stlink 1.7.0 开发库和系统主机 C 编译器。

单独的只读 Flash 备份入口（不主动复位/暂停）：

```bash
/usr/bin/python3 tools/f103_swd.py backup --output captures/new_flash_backup
```

注意：上游 st-flash 1.7.0 即便执行 read 也调用 `stlink_force_debug` 暂停 CPU，因此本项目的持续采集和备份采用独立只读 API 包装，不调用 st-flash read。
