# F103 双 IMU 到树莓派 SPI 接收的连续回传版本

2026-11-18，用户确认将接收侧 8 针无线模块从 USB RX 底板取下，直接连接树莓派 SPI。此次新增 `radio-stream` 固件构建配置，取消为旧 USB 底板设置的 300 ms 分片等待，按 IMU 有效输出逐帧发送。

**状态：代码、离线测试、固件构建和烧录预览已完成；没有烧录、复位或访问实物，也没有部署树莓派接收程序。不能宣称真实无线已达到 25 Hz。** 本次只修改独立铰接小车的采集回传代码，仿真导航、钻孔小车和车辆移动接口均不改动。

## 频率和发送行为

- 依据此前实测，当前两只 IMU 的 UART 输出各约 25 Hz，即每只约 40 ms 一个有效帧。新固件每得到一个有效帧就编码、入队，空闲时及时发送，不按固定定时器重复旧样本，也不主动把 25 Hz 降到 0.83 Hz。
- 每个 32 字节 `telemetry_v1` 样本用一个 32 字节无线载荷发送，保留前后身份、采集序号、MCU UART 收帧时间、启动编号和 CRC16。取消 16+16 分片及 300 ms 人工等待。
- 前后传感器分别排队、公平轮询。两路各 25 Hz 时目标合计 50 个样本包/秒，纯应用数据 1600 B/s，不再经过旧 USB 底板的 9600 波特率输出。
- 程序不修改 IMU 输出设置、不启用 MCU UART TX。未来若 IMU 输出更快，调度器会跟随有效帧；较高输入速率的离线测试不等于已改变或实测 IMU 频率。
- 连续运行，取消原先上电约 5 秒才发射、65 秒后停止的台架窗口。无线完成初始化后保留 2 ms 电源稳定时间，随后按有效数据发送。没有数据时不生成或补齐测量值。

## 队列和异常处理

每只 IMU 有 4 个待发样本槽。正常负载下逐帧保留，队列满时丢弃最旧待发样本并增加 `rf_queue_overflow_drops`；选包时超过 100 ms 的旧样本不再发送，计入 `rf_stale_drops`。100 ms 是发送前的排队新鲜度限制，不是已证明的端到端延迟上限。

射频硬件最多重传 3 次，失败释放当前包，让其他新样本继续处理；没有无限应用重传。TX 完成保护超时为 100 ms，成功或 MAX_RT 出现时立即推进，不等满该时长。按 250 kbps、32 字节和 ACK 的名义时序，正常交易约毫秒量级，100 ms 留有数十倍余量；尚未用实物测量正常交易时间。

SPI 标称 500 kHz，每字节名义传输 16 µs。新配置的单字节保护超时为 1 ms，超过名义时间 60 倍，避免故障时每字节阻塞 100 ms 并拖慢 UART 处理。此处同样是工程时序预算，后续实测应记录并核对有效余量。数据新鲜度阈值与通信操作保护超时分开处理。

无线活动期间主循环继续服务 CE 脉冲和 TX 状态，不因空 UART 队列而每次额外睡眠 1 ms；UART 中断仍只存字节事件，解析、编码和无线排队均在主循环执行。保留 UART 错误、UART 队列丢失、无线失败及 SPI 错误计数。

## 树莓派接收端必须匹配的参数

配置文件：`configs/radio_spi_stream.json`。这是裸模块 SPI 接收配置，与旧 USB RX 底板的转发固件不同。

| 项目 | 新固件与接收端约定 |
|---|---|
| 信道 / 空中速率 | 60，即 2460 MHz / 250 kbps |
| 无线地址 | 按 SPI 实际写入顺序为 `34 43 10 10 01`，5 字节 |
| 载荷 | 固定 32 字节 |
| 动态载荷 / ACK 载荷 | 均关闭，`DYNPD=0`、`FEATURE=0` |
| 射频硬件 CRC | 1 字节；不要无意使用库默认的 2 字节 CRC |
| 硬件自动应答 | pipe0 开启；这不是反向应用控制通道 |
| TX 重传 | 间隔 750 µs，最多重传 3 次 |
| 应用数据 | `telemetry_v1`，32 字节，小端，CRC16/CCITT-FALSE |

接收侧主要寄存器：`CONFIG=0x0B`、`EN_AA=0x01`、`EN_RXADDR=0x01`、`SETUP_AW=0x03`、`RF_CH=0x3C`、`RF_SETUP=0x26`、`DYNPD=0x00`、`FEATURE=0x00`、`RX_PW_P0=0x20`。pipe0 地址按上述字节数组写入，不要把不同库显示的十六进制整数地址直接当作同一字节顺序。

树莓派应及时排空接收 FIFO，不添加 100/300 ms 接收等待。每个载荷直接交给现有 `Packet.decode` 和 `ReceiverState.accept`，分别保留 MCU 收帧计时与树莓派单调接收时间。频率相符不代表延迟已验证，也不代表两只 IMU 内部采样时钟已同步。

本次不启用树莓派 SPI、不占用 GPIO、不登录或修改树莓派系统。接线、电源裕量、实际接收速率、延迟、距离和长期稳定性均需后续独立验证。

## 诊断和监视器

SRAM 诊断区位置、256 字节大小与基础 ABI 保持不变。无线扩展 `profile=3` 表示新连续整包配置；历史 USB 台架为 `profile=2`。新扩展按顺序包含启动编号、状态、完成包、失败包、尝试包、编码错误、SPI 错误、RF 队列溢出丢弃、RF 过期丢弃、最后状态、待发数量、高水位、排队年龄阈值、初始化错误和 TX 保护超时。

`packets_completed` 仅表示发射侧观察到 TX_DS，即硬件交易完成，不等于树莓派应用已经读取、校验和保存。必须另取树莓派实收的有效序号与 CRC 记录，不能只用 MCU 完成计数宣称每只已实收 25 Hz。

Git 维护目录中的电脑监视器已支持 profile 3，显示连续包计数与队列异常；不再等待 65 秒窗口结束或把新版本与旧 USB 接收卡片做交付核对。ST-Link 旁路仍只是源端抽样，不能代替树莓派 SPI 实收。旧桌面菜单和历史目录若仍指向旧代码，不应当作新配置的监视入口。
